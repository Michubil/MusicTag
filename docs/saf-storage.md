# 音频与 SAF 安全

相关代码：`data/flac`、`id3`、`wav`、`lyrics`、`storage`、`io`、`rename`。改动前读对应实现和测试。

## 标签契约

- FLAC 用 Vorbis Comment/PICTURE；MP3 读写 ID3v2.3 / ID3v2.4，目标版本跟随设置（默认 2.4）；标准 WAV 用内嵌 ID3v2.4，覆盖时同步已有 LIST/INFO。不适配 ID3v2.2 或 NCM。
- 只改选中的八项字段；关闭覆盖只补缺失。Available / ConfirmedAbsent / Unavailable 区分有效值、确认不存在和获取失败；获取失败不能删除已有值。
- 保留未知/自定义标签、多值艺术家、非正面封面；不清空标签区重建，不重编码。写后重新解析并比较音频载荷 SHA-256。
- 标题不附加别名；无依据不补编号/总数。日期写 DATE/TDRC，ID3v2.3 用 TYER/TDAT/TIME，不能完整表达的日期同时保留在 TXXX:DATE；歌词写 LYRICS/USLT 中的 LRC 文本，不写 SYLT 或外置 LRC。
- ID3v2.3 写入 UTF-16、普通帧长度和整标签反同步；版本转换保留可转换帧。遇到无法无损转换的特殊帧时，在替换原文件前报错，可选择原版本编辑。
- 嵌入原始 JPEG/PNG；歌词用原文与已有翻译按时间对齐，容差 200 ms，不按行号或机器翻译拼接。时间轴格式化默认截去第三位毫秒。
- 不新增 Song ID、指纹、匹配结果或 163key 到标签/日志/导出；已有私有字段保留。

## 授权与浏览

- 只通过 SAF 持久读写授权访问用户目录，授权目录就是导航 Root；URI/文档 ID 不透明，不解析磁盘路径。
- 取消、只读或授权失败保留原目录，新授权保存成功后才释放旧授权。
- 授权检查结束前显示加载；暂时读取失败不当作授权丢失。刷新保留有效选择，加载/写入时不重复刷新。
- 本地文件任务共用按 `Runtime.availableProcessors()` 设置的 I/O 调度器，批处理使用等量工作协程、保持结果顺序；仅为可见条目读取标签/封面，离开时取消。FLAC/MP3 预览只复制头部标签（上限 32 MiB），WAV 预览和编辑仍使用完整私有副本；预览副本不得用于写入。文字和封面复用一次解析，预览先交付显示，再在同一有并发上限的任务内压缩、保存缓存；取消或缓存失效仍阻止旧数据回写。
- 重命名预览并发读取标签。FLAC 从 SAF 流读取至首个 Vorbis Comment 块后停止，跳过其他块，不复制音频；MP3 只复制头部标签，WAV 保留完整读取。每个父目录只获取一次预览冲突列表；实际重命名前仍重新检查原文件和同目录冲突。
- 文件夹切换保留已知相对路径（Android LruCache，最多 128 项），刷新或更换授权后清除。Room 在授权与恢复检查后提供上次目录列表，再通过 SAF 重新查询；缓存展示期间可进入子目录，但不能选择或写入。查询接入 CancellationSignal，切换时取消旧查询，提供方仍须支持取消。
- 选择按 URI 去重，递归防循环；匹配、重命名和手动编辑共用全局递归和音频过滤设置。排除路径用授权目录内的显示名解析，不拆解文档 ID；时长读取失败时保留文件。
- 时长使用最多 2048 项内存 LRU 和 Room 持久缓存；时长与预览按授权树、URI、文件名、大小、修改时间匹配，缺少可靠大小/修改时间或读取失败时不持久缓存。时长并发跟随本地任务上限，取消后不继续扫描；FLAC 优先只读 42 字节 STREAMINFO，WAV 只读 fmt/data 头，其他情况用系统解析器。匹配与过滤使用同一套算法；MP3 没有容器内时长，匹配复用已探针或缓存的时长。
- Room 时长查询按授权树和 URI 分批读取（每批最多 400 项），筛选完成后仅批量保存缓存未命中的有效时长，并在事务内统一裁剪。目录使用 Upsert 和条目差异更新，未变化的子项不重写；目录条目索引包含排序位置。JSON 和缩略图编解码在后台、数据库锁外执行，单项预览损坏不禁用其他缓存。
- Room 位于私有 noBackupFilesDir，最多保存 128 个目录快照（合计 50000 个条目，逐行存储）、20000 项时长、512 项标签/缩略图预览（缩略图每项 128 KiB）。目录超限时正常实时读取。手动刷新清除当前树的缓存，换授权清除原树，写入/重命名失效原文件和父目录快照；未完成写入恢复前清除该树缓存。新列表确认删除或变化时移除对应预览与时长；目录快照被裁剪后删除不再属于任何目录条目的预览和时长。授权成功后在后台遍历仍存在的目录和文件，按 URI 保留缓存，去掉已删除或已不在原位置的歌曲；不依赖搜索。搜索会再做一次同样的保留。缓存失败退回 SAF，取消或失效前启动的读取不得重新写入缓存；缓存不替代提交前校验，不保存匹配历史或任务状态。
- 清缓存和文件失效操作完成后才响应取消，避免快速切换中断清理；缓存读取在返回前再次核对失效代次。缓存结构升级可直接重建数据库，不迁移或删除独立设置及 SAF 恢复记录。

## 标签提交与恢复

SAF 没有统一原子覆盖或目录锁。必须检查创建/重命名/删除能力，不以写模式打开原件。

1. 复制到私有 cache/saf-work 时同步计算全文摘要；手动编辑保存前还需匹配表单读取时的摘要。Editor 改标签并校验音频载荷。
2. 核对原 URI、名称、内容未变，保存最小恢复记录。
3. 同目录创建 `.musictag-new-UUID.ext`，上传并读回校验；再核对原件。
4. 原件暂存为 `.musictag-original-UUID.ext`，新副本恢复原名；每步使用返回 URI 并校验。
5. 最终验证成功才删除原件副本和记录；不确定时保留副本，暂停写入。

读取、编辑准备和独立文件重命名跟随本地任务并发上限；远程元数据查询单独限制四路，安全替换原文件的最终提交串行且不在中途取消。等待提交的任务挂起而不占用本地 I/O 线程。处理进度统计已结束的文件任务（包括失败），汇总另列成功、跳过和失败。noBackupFilesDir/saf-writes 仅记录未完成单文件的 URI、名称和摘要，完成/恢复后删除。启动、回到应用或刷新时先恢复；未恢复前不换目录或继续写入。浏览隐藏 `.musictag-` 文件，清理缓存不能删除恢复记录。

独立重命名只调用 renameDocument，不走标签替换流程。预览和执行前检查同目录冲突及原文件状态；不覆盖、不删文件、不盲目回滚，采用返回 URI 并刷新。

校验不能消除最后检查后的竞争。提供方异常、清除应用数据、卸载或文件系统损坏不在自动恢复保证内。DocumentStore 模拟测试不替代实际提供方的授权、低空间、中断和恢复验收。
